Users & Roles

शिवसेना
LIVE

A news portal is a multi-sided system. Each role below touches the same content database through a different permission surface. Getting these boundaries right is what keeps a high-volume newsroom stable.

Readers

All sections, regional news, galleries, web stories and podcasts open to the public. No login required — essential for maximum reach and Google Discover eligibility.

Authors

Write stories, upload media, apply categories and tags, and submit for review. Each author gets a public profile page that builds named credibility. Cannot publish directly.

Moderators

Verify facts, headline quality, image rights and language consistency. Approve, return with notes, or reject. Also own the Fact Check section and comment queue.

Editors

Publish and schedule stories, control homepage layout, trigger breaking news, assign featured stories. This is the role that runs the portal day to day.

Advertisers

Supply creatives and view placement performance and impression reports. No access whatsoever to editorial content or the CMS core.

Admin

Users and roles, site settings, plugins, SEO configuration, backups, security policy, ad management and analytics. Two-factor authentication mandatory.

Why this matters operationally: portals fail when everyone is an administrator. Strict role separation protects against accidental deletion, unauthorised publishing and security compromise — and makes the newsroom auditable, with every published story carrying a traceable author, moderator and publisher record.

RedisIn-memory object cache between PHP and MySQL. A news homepage runs dozens of database queries per load — Redis serves them from RAM, cutting response time dramatically at peak.

LiteSpeed / WP RocketFull-page caching, critical CSS and script deferral — converting a dynamic PHP page into a static HTML response for the vast majority of readers.
Image OptimisationAutomatic compression, responsive sizes and WebP conversion at upload. Images are 60–70% of a news page's weight — the single highest-impact performance intervention available.
Schema.org Structured DataNewsArticle, Organisation, Person and BreadcrumbList markup. Without valid structured data Google cannot classify the portal as a news publisher — which forfeits News and Discover placement entirely.

Security Framework

शिवसेना
LIVE

A portal covering politics attracts far more hostile attention than a typical business website. Security is therefore scoped here as core infrastructure, not an optional add-on.

SSL / TLS

Full HTTPS enforcement, automatic certificate renewal, HSTS headers and mixed-content elimination across every page.

Firewall (WAF)

Dual-layer — Cloudflare edge plus application-level. SQL injection and XSS attempts are stopped before reaching the code.

Malware Scanning

Scheduled integrity checks of core, theme and plugin files. Any unauthorised file change triggers an immediate alert.

Automated Backups

Daily database and weekly file backups held off-server. The restore procedure is physically tested during handover.

Login Security

Custom admin URL, rate limiting with IP lockout, strong password enforcement and mandatory 2FA for Editor and Admin roles.

Spam Protection

Honeypots and rate limiting on all forms, comment spam filtering, edge bot detection and throttling on the news-tip form.

Monitoring

Uptime monitoring with instant notification, SSL expiry alerts, file-change alerts and error-log review.

Access Governance

Least-privilege roles, no shared accounts, activity logging on every publish and setting change, and a documented offboarding process.

Step 1 — What one article really stores

Component of a single articleStored
Featured image as uploaded by the desk (before optimisation)~800 KB
6 auto-generated responsive sizes plus WebP variants (150px → 2048px)~560 KB
3 in-body images, same treatment applied~1,080 KB
Article HTML, revisions, tags and metadata in the database~60 KB
Total stored per published article~2.5 MB

The 20 KB figure is what the reader downloads — not what the server keeps. WordPress retains the original upload plus six responsive derivatives for every image, so stored size runs roughly 7× the delivered size. That multiple is what fills a disk.

Step 4 — Bandwidth is the bigger cost

  • 110,000 pageviews/day at launch targets — 50,000 sessions × 2.2 pages
  • ~1.1 MB average delivered page, including images, embeds and ad scripts
  • = 121 GB per day, or ~3.6 TB delivered per month
  • Cloudflare absorbs ~70% — leaving ~1.1 TB/month hitting your origin server
  • Election result day or major event: 5–8× normal load in a six-hour window

What a ₹5,000 server actually costs you

  • Disk exhausted in 14–18 months → emergency migration, usually mid-election-cycle
  • Bandwidth overage billed at penalty rates precisely when a story goes viral
  • 4 vCPU / 8 GB exhausts PHP workers at the 8–11 PM peak → slow pages or 502 errors on your biggest hour
  • Backups on the same disk — a compromised server destroys them with it; and unmanaged plans make OS patching your team's problem, or nobody's

Our position: this is not us specifying an expensive server. It is us specifying the server that will still be adequate in month 30 — because migrating a live news portal under load is the most expensive item on this page.
